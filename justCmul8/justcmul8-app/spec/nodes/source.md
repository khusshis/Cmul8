# Source Node Specification

## Overview
The \`source\` node acts as the generator or entry point for entities into the simulation system. It is responsible for creating entities (e.g., customers, messages, patients, tasks) and releasing them into the downstream network based on defined arrival patterns.

## Parameters
The source node configuration determines how and when entities are created.

### 1. Arrival Timing
- **Arrival Rate**: The mean number of entities generated per simulation time unit. 
- **Distribution**: The statistical distribution used to sample inter-arrival times. Options include:
  - \`exponential\`: Random, memoryless arrivals (Poisson process). Most common for modeling natural arrivals.
  - \`uniform\`: Arrivals occur randomly within a specified minimum and maximum range.
  - \`normal\`: Arrivals follow a Gaussian distribution around a mean.
  - \`deterministic\`: Arrivals occur at strictly fixed intervals.
  - \`poisson\`: Similar to exponential but parameterized differently depending on engine implementation.

### 2. Cap / Infinite Options
- **Infinite Arrivals**: A boolean flag. If true, the source generates entities indefinitely until the simulation ends.
- **Max Entities**: A hard cap on the total number of entities this source can spawn. Once reached, the source stops generating.

### 3. Arrival Schedule (Timetable)
Instead of a continuous rate, a source can operate on a discrete schedule.
- **Schedule**: A list of batches defined by:
  - \`simTime\`: The exact simulation time at which the batch arrives.
  - \`count\`: The number of entities generated in this batch.
- **Schedule Recurring**: If true, the schedule loops from the beginning once the final scheduled batch has been emitted.

### 4. Entity Attributes
Every entity generated by this source is stamped with attributes that can affect downstream processing.
- **Entity Class / Type**: A logical category (e.g., \`customer\`, \`vip\`, \`patient\`). Useful for downstream \`decision\` nodes to route differently based on class.
- **Priority Level**: Default priority (\`standard\`, \`priority\`, \`urgent\`). Determines processing order when arriving at a \`priority_resource\` or \`queue\`.

### 5. Routing Logic
Determines how the generated entities are passed to connected output nodes.
- **Routing Mode**:
  - \`round_robin\`: Entities alternate evenly across all connected outgoing paths.
  - \`broadcast\`: A copy of the entity is sent down ALL connected outgoing paths simultaneously.
  - \`priority\`: Entities are routed based on their class/priority (requires downstream configuration).

## Operational Behavior
1. The simulation engine calculates the next arrival time based on the selected distribution and rate, or the explicit schedule.
2. The simulation advances to that time.
3. The source instantiates a new entity, assigning it an ID, its class, priority, and the current simulation time.
4. The entity is immediately pushed to the next node according to the \`Routing Mode\`.
5. The source schedules its next creation event.

## Metrics Tracking
- **Entities Out**: Total number of entities successfully generated and pushed out.
