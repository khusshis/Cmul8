# Feature: One-Click AI System Optimizer

## Status before this feature
**Partial (~25%), and currently mislabeled.** `analyticsEngine.ts:555-621`'s `generateExecutiveDiagnosis()` produces `result.aiDiagnosis` (title/summary/bottleneckCause/recommendations), which `ExecutiveTab.tsx:371-404` displays as "Smart Recommendations to Speed Up Flow" cards — but this function is a **deterministic if/else template** (`if (healthScore < 70) { title = "Traffic Jam Alert..." }`, `analyticsEngine.ts:571-577`). It never imports `modelRouter.ts` or calls Gemini. It should not be presented as AI-generated. There is also **no "Apply Fix" action anywhere** — grep confirms zero matches for `applyFix`/`apply.?fix` in `src/`. The recommendation cards are read-only text.

## What this feature does
Two upgrades to the existing (mislabeled) diagnosis system:
1. Make the diagnosis genuinely AI-generated by routing the bottleneck/telemetry data through Gemini (reusing the exact same `modelRouter.ts` infrastructure the AI Assistant chat already uses).
2. Give each recommendation a structured, machine-applicable "fix" payload, and add a one-click **"Apply Fix"** button that patches the live graph — reusing the exact `upsertNodes`/`applyAIOps` mechanism the AI Chat panel already uses to apply AI-suggested graph changes.

This is the feature the pitch calls "autonomous problem diagnosis and prescriptive analytics" — the key differentiator from a chatbot is that it doesn't just describe the fix, it can apply it.

## Implementation plan

### Step 1 — New API route: real AI-driven bottleneck diagnosis

New file: `src/app/api/ai/optimize/route.ts`

Model this directly on `src/app/api/ai/chat/route.ts` (same imports, same rate-limit pattern, same `generateJSON`/`extractJSON` call shape — that file already demonstrates the exact pattern for calling Gemini with a system prompt and parsing structured JSON back out):

```ts
import { NextResponse } from "next/server";
import { createClient } from "@/lib/supabase/server";
import { generateJSON, extractJSON, AIRouterError } from "@/lib/ai/modelRouter";
import type { SimResult, SimTypeId } from "@/lib/simulation/types";
import { SIM_TYPE_REGISTRY } from "@/lib/simulation/simTypeRegistry";

export const maxDuration = 60;

// Reuse the same per-user rate-limit pattern already implemented in chat/route.ts
// (copy RATE_WINDOW_MS/RATE_MAX/recent/rateLimited from there, or factor it into a
// shared src/lib/ai/rateLimit.ts if implementing both routes in the same PR).

export interface OptimizerFix {
  nodeId: string;
  paramPatch: Record<string, number | string | boolean>;
  description: string;   // human-readable, e.g. "Increase capacity from 2 to 3"
}

export interface OptimizerRecommendation {
  title: string;
  action: string;
  impact: string;
  confidence: number;
  fix?: OptimizerFix;   // present only when the recommendation is mechanically applicable
}

export async function POST(req: Request) {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

  const body = await req.json();
  const result: SimResult = body.result;
  const simType: SimTypeId = body.simType;
  if (!result || !simType) {
    return NextResponse.json({ error: "Missing result or simType" }, { status: 400 });
  }

  const config = SIM_TYPE_REGISTRY[simType];
  const bottleneck = result.bottleneckNodeId ? result.nodeStats[result.bottleneckNodeId] : null;

  // Keep the payload small and structured — do not send raw logs (result.logs can be huge).
  const telemetrySummary = {
    domain: config.label,
    totalArrived: result.totalArrived,
    totalCompleted: result.totalCompleted,
    healthScore: result.healthScore,
    bottleneck: bottleneck
      ? {
          nodeId: result.bottleneckNodeId,
          label: bottleneck.label,
          nodeType: bottleneck.nodeType,
          utilization: bottleneck.utilization,
          avgWaitTime: bottleneck.avgWaitTime,
          currentCapacity: (bottleneck as any).capacity, // present on resource/queue nodeStats when applicable
        }
      : null,
    littlesLawStable: result.littlesLaw?.isStable,
    waitP95: result.waitTimePercentiles?.p95,
  };

  const systemInstruction = `You are a discrete-event-simulation optimization engine for JustCmul8, a queueing/DES platform.
Given telemetry from a completed simulation run, diagnose the primary bottleneck and propose 1-3 concrete, mechanically
applicable fixes. Respond with STRICT JSON matching this shape, and nothing else:
{
  "recommendations": [
    {
      "title": "string, <=60 chars",
      "action": "string, plain-English explanation",
      "impact": "string, expected quantitative effect",
      "confidence": number (0-100),
      "fix": {
        "nodeId": "string, must match a nodeId from the provided telemetry",
        "paramPatch": { "capacity": number },
        "description": "string, <=80 chars, e.g. 'Increase capacity from 2 to 3'"
      }
    }
  ]
}
Only include a "fix" object when you can name a specific node parameter to change (e.g. resource capacity,
queue capacity, arrival rate). Valid paramPatch keys depend on node type: resource/priority_resource → capacity,
serviceTimeMean; queue → capacity; source → arrivalRate. Do not invent parameter names outside these.`;

  try {
    const { text } = await generateJSON({
      systemInstruction,
      prompt: `Simulation telemetry:\n${JSON.stringify(telemetrySummary, null, 2)}`,
      maxOutputTokens: 1024,
      temperature: 0.3,
    });
    const parsed = extractJSON(text);
    if (!parsed?.recommendations) {
      return NextResponse.json({ error: "AI response did not contain recommendations" }, { status: 502 });
    }
    return NextResponse.json({ recommendations: parsed.recommendations as OptimizerRecommendation[] });
  } catch (err) {
    if (err instanceof AIRouterError) {
      return NextResponse.json({ error: err.message }, { status: err.status });
    }
    return NextResponse.json({ error: "Optimization failed" }, { status: 500 });
  }
}
```

**Validate the fix payload server-side before trusting it** — the same way `graphOps.ts`'s `normalizeAIResponse()` already coerces/validates raw AI output before it's allowed to touch the canvas (`num()`, `str()`, `isNodeType()` helpers at `graphOps.ts:80-91`). Do not let the model's `paramPatch` apply arbitrary keys to arbitrary nodes unchecked — at minimum verify `nodeId` exists in the current graph and `paramPatch` keys are in an allowlist per node type before returning the response, or before applying it client-side in Step 3.

### Step 2 — Wire the new route into the Executive tab

File: `src/components/workspace/results-dashboard/ExecutiveTab.tsx`

Currently (lines 371-404), `aiDiagnosis?.recommendations?.map(...)` renders static cards fed by the deterministic `analyticsEngine.ts` function. Replace/augment this with a client-side fetch to the new route:

```tsx
const [aiRecs, setAiRecs] = useState<OptimizerRecommendation[] | null>(null);
const [aiLoading, setAiLoading] = useState(false);

async function runAiOptimizer() {
  setAiLoading(true);
  try {
    const res = await fetch("/api/ai/optimize", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ result, simType }),
    });
    const data = await res.json();
    if (data.recommendations) setAiRecs(data.recommendations);
  } finally {
    setAiLoading(false);
  }
}
```

Add a button above the recommendations list:

```tsx
<button
  onClick={runAiOptimizer}
  disabled={aiLoading}
  className="flex items-center gap-1.5 px-3 py-1.5 rounded-xl bg-[#5742FF] text-white text-[11.5px] font-bold hover:bg-[#4835E0] transition-all disabled:opacity-60"
>
  <Sparkles size={13} />
  {aiLoading ? "Analyzing..." : "✨ Optimize System with AI"}
</button>
```

Keep the existing deterministic `aiDiagnosis` (rename its UI label from "AI Performance Summary" to something honest like "Automated Performance Summary" while you're in this file, since it's not actually LLM-driven — or wire the same real Gemini call into the summary text too, reusing `telemetrySummary` from Step 1) as the default/fallback shown before the user clicks the button, and swap to `aiRecs` (real Gemini output) once the button is clicked and resolves. This gives instant free feedback (the existing rule-based version) plus an upgrade path to real AI on demand — mirrors how `AIChatPanel.tsx` already treats AI calls as an explicit user action, not something that fires automatically on every render.

### Step 3 — "Apply Fix" button, using the existing `applyAIOps` mechanism

The AI Chat panel already has a working pattern for turning AI output into a live graph mutation: `applyAIOps(currentNodes, currentEdges, ops)` in `src/lib/ai/graphOps.ts:559`, called from `AIChatPanel.tsx` and passed up via the `onApplyChanges(nodes, edges)` prop that `page.tsx:776` wires to `setNodes`/`setEdges` + autosave. Reuse this exact mechanism instead of inventing a new one.

`AIGraphOps.upsertNodes: AINodePatch[]` (`graphOps.ts:62`) is precisely "patch these node IDs with these param changes" — which is what an `OptimizerFix` is. In `ExecutiveTab.tsx`, accept an `onApplyFix` callback prop (passed down from `AdvancedResultsDashboard.tsx`, which itself needs a new prop threaded from `page.tsx`, similar to how `onApplyChanges` is already threaded to `AIChatPanel`):

```tsx
// ExecutiveTab.tsx
function handleApplyFix(fix: OptimizerFix) {
  const ops: AIGraphOps = {
    actionType: "PATCH_GRAPH", // check graphOps.ts's AIActionType union for the exact existing value name to reuse — do not invent a new actionType if PATCH/UPDATE already exists
    upsertNodes: [{ id: fix.nodeId, params: fix.paramPatch }] as any, // shape must match AINodePatch — read graphOps.ts's AINodePatch interface before wiring this
    addEdges: [],
    deleteNodeIds: [],
    deleteEdgeIds: [],
  };
  onApplyFix(ops); // bubbles up to page.tsx, which calls applyAIOps + onUpdateNodes/onUpdateEdges exactly like AIChatPanel does
}
```

```tsx
{rec.fix && (
  <button
    onClick={() => handleApplyFix(rec.fix!)}
    className="mt-2 px-3 py-1 rounded-lg bg-emerald-50 text-emerald-700 text-[11px] font-bold hover:bg-emerald-100 transition-all"
  >
    ⚡ Apply Fix: {rec.fix.description}
  </button>
)}
```

**Read `AINodePatch` and `AIActionType` in `src/lib/ai/graphOps.ts` before wiring this** — the exact field names/action type string must match what `applyAIOps()` expects, since that function does real validation and will silently no-op or warn on a malformed op object. Do not guess the shape from this MD alone; open the file.

Wire the callback chain: `page.tsx` already has `onUpdateNodes`/`onUpdateEdges` (line 171/177) — write a small `applyOptimizerFix(ops: AIGraphOps)` function in `page.tsx` that calls `applyAIOps(nodes, edges, ops)` and feeds the result into those same setters, then pass it down through `AdvancedResultsDashboard` → `ExecutiveTab` as a new prop.

### Step 4 — Show a confirmation toast after applying

Reuse the existing `toast` utility already imported in `page.tsx` (used at `handleRun`/`engine.onError`, e.g. `toast.error(...)`) to show `toast.success("Applied fix: increased capacity to 3", "Optimization Applied")` after a fix is applied, and consider auto-triggering a re-run (`handleRun()`) so the user immediately sees the improved health score — this closes the loop the pitch describes: *diagnose → apply → see the improvement*, all in one click plus one re-run click.
